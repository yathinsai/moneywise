# MoneyWise Gen Z — Sai's Student-Led Passion Project Strategy

## Project vision

**MoneyWise Gen Z** is a student-led financial literacy initiative that helps younger teens learn money and business skills by **making decisions, seeing consequences, and trying again**. Instead of a static lesson or a chatbot that merely marks answers correct, students use virtual money to navigate relatable choices about saving, budgeting, inflation, investing basics, and running a small business.

**Core learning loop:** Learn → Decide → See Consequences → Reflect → Try Again.

**Initial audience:** Grades 6–8. **Long-term audience:** Ages 12–19, with age-specific modules.

**Student leader:** Sai, an 11th-grade student interested in finance and business. Sai should own the problem definition, curriculum, scenario design, outreach, facilitation, feedback analysis, and project story. A parent or mentor can help with code review and technical guidance, but the work presented as Sai's must accurately reflect his contributions.

## The three connected activities

### 1. BUILD — Create the interactive financial decision simulator

**Goal:** Release a small, functional, mobile-friendly app that students can use without an account.

**MVP features**
- Conversational, rule-based coach with short prompts and 2–4 choices.
- Virtual wallet/savings balances and visible consequences after each decision.
- Branching scenarios, clear explanations, and a restart button.
- Five introductory topics: budgeting, saving, inflation, investing fundamentals, and small-business decisions.
- Local progress saved in the browser; no personal student data collected.
- Accessible text labels for feedback, not color alone.

**Initial content:** 10 branching scenarios, 20 reviewed quiz questions, and 20 FAQs. For each scenario, define the learning objective, starting balances, choices, consequences, explanation, and takeaway. Avoid suggesting that every financial trade-off has one universally correct answer.

**Tech stack:** One lightweight HTML/CSS/VanillaJS interface, static JSON content, `localStorage`, and GitHub Pages. No paid AI API, backend, or authentication for the MVP.

**Deliverables:** Live website, public GitHub repository, README, scenario content, and a short demo video. Sai should be able to explain the product decisions and how the simulator works.

### 2. TEACH — Run community financial literacy workshops

**Goal:** Use the simulator as a teaching tool in real 45-minute sessions for middle-school students.

**Potential partners:** Public libraries, school clubs, youth organizations, and community centers. Confirm venue permissions, age requirements, safeguarding policies, and whether an adult facilitator is required before scheduling.

**45-minute pilot workshop**
| Minutes | Activity |
|---|---|
| 0–5 | Welcome, objectives, anonymous baseline questions |
| 5–10 | Introduce needs vs. wants and a simple budget |
| 10–25 | Students play two or three simulator scenarios |
| 25–35 | Discuss trade-offs in small groups |
| 35–40 | Repeat key questions to check learning |
| 40–45 | Feedback, one practical takeaway, closing |

**Sai's role:** Prepare materials, recruit participants through approved channels, present the concepts, guide discussions, and adjust future sessions based on student questions.

**Deliverables:** Facilitator guide, slides/handout, session agenda, partner outreach message, and workshop log.

### 3. MEASURE — Demonstrate learning and improve the product

**Goal:** Gather evidence that the experience is understandable, engaging, and educational—not just that the website exists.

**Useful measures**
- Reach: workshops conducted and participants attending.
- Engagement: scenarios completed and optional completion rate.
- Learning: anonymous pre/post results using the same or equivalent questions.
- Experience: brief anonymous ratings for clarity, relevance, and enjoyment.
- Improvement: number of content or UI changes made because of feedback.

**Privacy:** Avoid collecting names, emails, exact ages, financial account details, or identifiable student information. Obtain venue/school permission and any required parent/guardian consent. Report only aggregate results. If the group is small, avoid publishing details that could identify individuals.

**Deliverables:** Simple results spreadsheet, version/change log, one-page impact report, and a short reflection about what did and did not work. Do not claim that the simulator caused long-term behavior change based only on a short workshop.

## Execution plan

### Phase 1 — One-week build sprint

| Day | Sai's priority | Outcome |
|---|---|---|
| 1 | Define grade 6–8 learner needs; select topics; sketch the experience | One-page problem statement and scenario outlines |
| 2 | Write and review questions, explanations, and scenario branches | Initial JSON content |
| 3 | Build conversational interface and choice handling | Working quiz flow |
| 4 | Add virtual balances, branching, and consequences | Working simulator flow |
| 5 | Add progress, restart, responsive design, accessibility checks | Usable MVP |
| 6 | Test with 3–5 peers; fix confusing scenarios | Feedback log and revisions |
| 7 | Publish to GitHub Pages and document usage | Live demo and README |

**Scope rule:** If time runs short, ship 3 polished scenarios and a reliable workshop-ready flow before adding more content. Ten scenarios is a content target, not a reason to delay the pilot.

### Phase 2 — First pilot (weeks 2–4)

1. Contact one library or youth organization with a concise workshop proposal.
2. Confirm logistics, audience, supervision, device/internet needs, and permissions.
3. Run one 45-minute pilot using the simulator.
4. Collect anonymous baseline/post-session responses and feedback.
5. Fix the three biggest issues; publish version 1.1.

### Phase 3 — Community expansion (months 2–3)

1. Run two additional workshops if partners and schedules allow.
2. Recruit a small student volunteer team with defined roles.
3. Add scenarios based on questions students actually ask.
4. Publish a short impact report with accurate metrics and limitations.
5. Prepare a repeatable workshop kit another student could use.

### Phase 4 — Sustainable student initiative (months 4–6)

- Build relationships with repeat community partners.
- Add age-specific modules, including introductory entrepreneurship.
- Train additional student facilitators and document quality standards.
- Review content for accuracy and accessibility each release.
- Decide whether new features are justified by actual learner needs.

## What success looks like

**Minimum success:** A working public simulator, one real pilot workshop, documented feedback, and one meaningful product iteration.

**Stretch goals (not promises):** Three workshops, 50–75 learners reached, measurable improvement on short knowledge checks, and a student-led facilitator team. Only publish numbers actually achieved.

## Why this can be a strong college passion project

MoneyWise Gen Z connects Sai's interest in **finance and business** with entrepreneurship, product development, leadership, and community service. For college applications, the strongest evidence is **authentic student ownership, sustained commitment, and measurable community value**, not the technical complexity of the app or the title “founder.” Admission outcomes, including at selective business programs, are never guaranteed by a single project.

Sai can document the project through a concise portfolio page containing the problem, his role, screenshots, live demo, workshop evidence (with permission), impact metrics, iterations, and personal reflection.

## Operating principles

1. **One learner first:** Start with grades 6–8 rather than designing for every teen at once.
2. **Simulation over memorization:** Teach decisions and consequences, not just quiz answers.
3. **Simple technology:** Build what Sai can explain and maintain.
4. **Real users before features:** Pilot early and prioritize observed problems.
5. **Responsible education:** Avoid individualized investment recommendations and misleading certainty; label hypothetical examples.
6. **Evidence over hype:** Measure honestly and distinguish participation, short-term learning, and lasting impact.
7. **Student ownership:** Keep Sai visibly responsible for the initiative's direction and delivery.
